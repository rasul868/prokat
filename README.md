# Архыз Booking v0.2 — обновление

## Обновление с v0.1 (Windows / PowerShell)

1. Остановите старый проект Ctrl+C. Сделайте копию всей папки и резервную копию PostgreSQL (pgAdmin → база arkhyz_booking → Backup).
2. Распакуйте ZIP, скопируйте содержимое папки arkhyz-booking поверх своей старой папки с заменой файлов. Архив не содержит .env, node_modules или настоящего QR, так что они сохранятся. Не создавайте заново базу, не удаляйте таблицы.
3. В существующий .env в самый низ добавьте:

```env
# Настройки будущего платёжного адаптера — пока пустые
PAYMENT_API_PROVIDER=
PAYMENT_API_SHOP_ID=
PAYMENT_API_KEY=
```

4. Выполните `npm install`, затем `npm start`. Добавление колонок выполняется автоматически при запуске. Прокат отключается, старые данные остаются. Для новой установки скопируйте .env.example в .env и создайте пустую базу arkhyz_booking.

## Администратор

- http://localhost:3000/admin/ — desktop, http://localhost:3000/admin/mobile/ — отдельная мобильная страница. Между ними есть переключатель. Логин и пароль из .env.
- Заказы: удалить из списка можно отменённые/истёкшие/возвращённые и выполненные после отметки выплаты. Неоплаченный заказ сначала отменяется. Заказ с оплатой необходимо сначала обработать. История денег сохраняется. Поздний перевод по скрытому заказу возвращает его в список проверки.
- Исполнители: анкета появляется после регистрации в Telegram, администратор указывает комиссию и тарифы, ставит галочку «Активен / одобрить». Пустые индивидуальные цены означают общий тариф. Удаление отключает доступ, не удаляет историю. Незавершённые оплачиваемые заказы нужно сначала обработать.
- Услуги и цены: взрослый и детский общие тарифы по лыжам/сноуборду, индивидуальные цены доступны из этого раздела и из карточки исполнителя. Цена за час за группу, как в v0.1; детей отличает выбранный тариф, не количество.
- Оплата: выбрать PNG/JPEG до 4 МБ либо вставить из буфера в область Ctrl+V, нажать «Сохранить QR». Файл хранится в QR_IMAGE_PATH. Для VPS/Render необходимо постоянное хранилище; иначе файл может пропасть при перезапуске/деплое.
- Журнал доставки — только технические ошибки отправки сообщений Telegram.

## Регистрация инструктора

Назначьте бота администратором закрытой группы инструкторов. INSTRUCTOR_GROUP_ID должен содержать ID именно этой группы. Новому участнику отправляется приветствие с кнопкой заполнения анкеты. Для уже состоящих в группе — команда /register в группе. Анкета продолжается в личном чате, поскольку Telegram не позволяет боту первым начать личный диалог. ID и username берутся из Telegram автоматически, имя инструктор вводит, специализацию выбирает. Администратор назначает цену и одобряет анкету. Рекомендуется каждому инструктору настроить публичный username в Telegram, чтобы турист мог открыть чат непосредственно из Mini App. Без username остаётся ссылка на профиль в сообщении бота (её доступность зависит от настроек Telegram).

## Mini App

Для локального просмотра: DEMO_MODE=true, LOCAL_PREVIEW=true. Виртуальному клиенту не отправляются сообщения.

Для теста внутри Telegram: поднимите HTTPS-туннель, например `cloudflared tunnel --url http://localhost:3000`, установите `PUBLIC_URL=https://...trycloudflare.com` (без /mini/), `LOCAL_PREVIEW=false`, оставьте `DEMO_MODE=true`, перезапустите. В личном чате бота нажмите /start → «Открыть бронирование». Можно настроить постоянную кнопку Menu в BotFather, указав полный адрес /mini/. Администраторы и инструкторы тоже должны открыть личный чат и нажать /start. ADMIN_TELEGRAM_IDS — личные ID администраторов, разделённые запятой. Не публикуйте токен, пароли и API-ключи.

Турист выбирает лыжи/сноуборд и взрослый либо детский тариф, время и количество. После отправки автоматически открывается «Мои заказы». SSE отправляет обновления примерно за 2,5 секунды, без обновления страницы. Цена до принятия ориентировочная, после принятия фиксируется по тарифу исполнителя. Клиент нажимает «Оплатить», видит QR и инструкцию, затем «Перевод выполнен». Администратору отправляется сообщение, CRM показывает проверку оплаты. После ручного подтверждения турист видит кнопку связи с инструктором и получает личное уведомление. Telegram требует действие пользователя для открытия чата.

## Настоящие платежи и будущий API

До использования реальных денег завершите тестовые заказы; лучше использовать отдельную чистую рабочую базу и отдельного бота. Проверьте правильность QR и имя получателя, убедитесь, что администратор получил тестовые уведомления. Затем DEMO_MODE=false, LOCAL_PREVIEW=false, PUBLIC_URL=https://..., ADMIN_TELEGRAM_IDS заполнены. Статический QR не отслеживает переводы и не подтверждает сумму: администратор проверяет банковскую выписку. Возврат также выполняется вручную в банке, только потом отмечается в CRM. На одном телефоне может потребоваться скриншот QR и импорт из галереи в банковском приложении.

Кнопка «Перейти на банковский API» и настройки .env подготовлены, но переключение блокируется до написания адаптера конкретного провайдера. Ключ сам по себе не делает интеграцию рабочей. Для настоящего API потребуется договор, создание платежа, проверяемые статусы/webhook, защита от повторных событий, обработка возвратов и тесты. Не используйте личный перевод для коммерческих расчётов без проверки условий банка, кассовых и правовых требований.

`npm test` — доменные тесты (6). `npm run check` — синтаксис основных файлов. Полный запуск с реальным PostgreSQL и Telegram в среде подготовки не проверялся. Проверьте регистрацию, двойное принятие, разные тарифы, QR, уведомления, возврат и мобильную CRM на тестовой базе перед запуском для клиентов.
